# PNG-спрайты Ребекки

Здесь хранятся шесть загруженных пользователем PNG. Их можно заменить собственной
пиксельной графикой: программа загружает ваши PNG, а без них показывает старую фигурку.
Никаких изображений из интернета приложение не скачивает.

```text
assets/
└── sprites/
    ├── README.md
    ├── idle.png     # спокойная стойка (по умолчанию)
    ├── walk.png     # один кадр ходьбы, без движения
    ├── sleep.png    # сон, только картинка
    ├── angry.png    # сердитая поза
    ├── happy.png    # радостная поза
    └── sit.png      # сидячая поза
```

Одиночные PNG необязательны: можно начать только с `idle.png`. Если выбранного файла нет, он повреждён,
слишком большой, без альфа-канала или полностью прозрачен, будет показана
временная фигурка и выведено предупреждение в консоль. Другие состояния
не подменяют отсутствующий файл: fallback всегда одинаковый.

## Требования к графике

- Один статичный кадр на файл, формат **PNG RGBA** (альфа-канал). Не GIF,
  не анимированный PNG и не лист нескольких кадров. Имена — строчные, как выше.
- Прозрачный фон, без нарисованной шахматной сетки, белого/чёрного прямоугольника.
  Для чёткого пиксельного стиля рекомендуются значения альфа 0 или 255.
- Рисуйте в исходном разрешении: например, **16×24** или **32×48 пикселей**.
  Максимум **64×96** на файл; больший кадр заменяется запасной фигуркой,
  чтобы случайный большой PNG не превратил окно в невидимую поверхность.
- Для набора используйте одинаковый размер холста, согласованную палитру,
  чёткий силуэт и одинаковый масштаб деталей. Опорная точка — середина
  нижнего края кадра. Ступни/основание позы располагайте на нижней строке,
  чтобы фигура стояла над панелью задач, а не висела из-за прозрачного отступа.
- Убирайте лишние прозрачные поля: всё окно, включая эти поля, получает клики.
  Отдельный попиксельный hit-test пока не реализован.
- Не увеличивайте PNG заранее. Параметр `--scale` умножает обе стороны на
  **1, 2, 3 или 4**, сохраняя пропорции и оригинал файла. Используется
  Nearest Neighbor: каждый исходный пиксель становится квадратом без смешивания
  цветов. Например, 32×48 при `--scale 3` даёт окно 96×144 логических пикселя.
  Масштаб Windows дополнительно влияет на физический размер на экране;
  чёткость при дробном системном DPI необходимо проверить на Windows.
- Используйте собственную графику или материалы с подходящими правами.

## Просмотр и масштаб (Windows PowerShell, из корня проекта)

```powershell
.\.venv\Scripts\python.exe -m rebecca --state idle --scale 2
.\.venv\Scripts\python.exe -m rebecca --state happy --scale 3
.\.venv\Scripts\python.exe -m rebecca --state sleep --scale 1
```

Закрывайте предыдущее окно через ПКМ → «Выход» перед следующим запуском.
Выбор состояния только показывает другой файл: персонаж не засыпает,
не сердится и не начинает ходить. Настройки не сохраняются. Чтобы увидеть
новую версию PNG после редактирования, перезапустите программу.

По умолчанию папка определяется относительно исходников, а не текущего
каталога PowerShell (используйте установку `pip install -e .`). Можно указать
другую папку, в том числе путь с пробелами:

```powershell
.\.venv\Scripts\python.exe -m rebecca --sprites-dir "C:\My Sprites" --state sit --scale 2
```

Все загрузки локальные и только для выбранного PNG. Дополнительные библиотеки,
готовые изображения, Win32 и сеть для этого этапа не требуются.

## Покадровая анимация (этап 04)

Для `idle` и `walk` поддерживается цикл из отдельных PNG (не спрайтовый лист).
Остальные состояния пока показывают одиночный кадр. Пример структуры:

```text
assets/
├── animations.example.json  # готовый шаблон из репозитория
├── animations.json          # активный манифест загруженных кадров
└── sprites/
    ├── idle.png             # прежний одиночный кадр и fallback
    ├── walk.png
    ├── idle/                # 12 кадров: 00.png–11.png
    │   ├── 00.png
    │   ├── 01.png
    │   ├── 02.png
    │   └── ... 11.png
    └── walk/                # 8 кадров: 00.png–07.png
        ├── 00.png
        ├── 01.png
        ├── 02.png
        └── ... 07.png
```

Кадры в подпапках уже загружены пользователем и подключены в `assets/animations.json`.
Для idle используются все 12 кадров по порядку с частотой 6 кадров/с, для walk —
все 8 кадров с частотой 8 кадров/с. Циклы длятся примерно 2 и 1 секунду соответственно.
Повторяющиеся кадры сохранены: это удержание позы в исходной последовательности.

Для другого набора можно отредактировать манифест или использовать шаблон
`assets/animations.example.json`. Например, описание двух кадров idle:

```json
{
  "version": 1,
  "animations": {
    "idle": {
      "fps": 4,
      "frames": ["idle/00.png", "idle/01.png"]
    }
  }
}
```

- `frames` задаёт точный порядок кадров: от 1 до 32. Последний переходит в первый.
- `fps` — целое число от 1 до 30, скорость смены кадров в секунду. Сейчас задано 6
  для idle и 8 для walk; для удержания позы можно повторять кадры в списке.
- Пути считаются относительно `assets/sprites`, PNG должны лежать внутри неё.
  При `--sprites-dir "C:\Art\sprites"` манифест ищется в `C:\Art\animations.json`.
- Все кадры одной анимации должны иметь **одинаковый холст** до 64×96, прозрачный
  фон и одну точку опоры ног. Масштаб увеличивает каждый кадр одинаково через
  Nearest Neighbor; направление меняется только при рисовании.
- Если один кадр отсутствует, повреждён или отличается размером, вся анимация
  заменяется соответствующим одиночным PNG. Не будет смеси разных размеров.
- Отсутствие манифеста или записи выбранного состояния — нормальный режим
  одиночного PNG. Повреждённый JSON даёт предупреждение и тот же fallback.
- Кадры читаются при запуске, а не при каждой перерисовке. После правки PNG или
  JSON перезапустите приложение. Сеть и библиотеки для генерации кадров не нужны.

Проверка настоящих кадров: `python -m rebecca --state idle --scale 2` или
`--state walk`. Walk меняет только изображение — перемещения по экрану нет.
Проверка без новых кадров: `--demo-animation --state idle` или
`--demo-animation --state walk` включает тестовую анимацию старой фигурки;
ваши картинки остаются на диске без изменений.

Пункт меню «Развернуть» и параметр `--facing left` отражают как одиночный PNG,
так и всю анимацию. Без отражения (`--facing right`) показывается оригинал.

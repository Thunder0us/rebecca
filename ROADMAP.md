## 2. Предлагаемый следующий минимальный этап — V01

**Цель:** разрешить более детализированные PNG без увеличения невидимой поверхности окна и неконтролируемого расхода памяти.

Состав только этого этапа:

- Заменить жёсткий потолок 64×96 проверкой заголовка/объёма источника и бюджета активного клипа. Предлагаемые значения: до 2048×2048 и 4 194 304 пикселей, до 16 МиБ на PNG; кэш активного клипа до 64 МиБ. Детали оценки — в ARCHITECTURE.
- Отделить размер исходника от желаемого масштаба и безопасного размера окна. По каждой оси окно не больше min(384 логических пикселя, 35% рабочей области), пропорции сохраняются. При смене экрана размер и позиция пересчитываются.
- Сохранить Nearest Neighbor, version=1 манифест, текущий набор кадров и CLI. Старые PNG 64×96 при --scale 2 остаются 128×192 на обычном экране.
- Ошибка источника или превышение памяти возвращает ограниченный fallback с понятной причиной. Не создавать новую процедурную графику; не менять существующие PNG.

Изменяемые области будущего кода: загрузчик/политика размеров, размещение окна и необходимые тесты. Точные файлы называются перед реализацией. **Не входят:** FSM, движение, смена состояния, переходы, портреты, тема, настройки GUI, инструменты и модели.

### Критерии проверки V01 на Windows

1. Старые idle/walk при --scale 2 показывают ваши кадры, сохраняют прозрачность, положение над панелью задач и размер 128×192 в обычной рабочей области; циклы не мерцают.
2. Собственный прозрачный PNG 256×384 загружается вместо заглушки. При масштабах 1–4 окно пропорционально вписывается в ограничения, целиком доступно; исходный PNG не меняется. Это повторяется при DPI 100/125/150/200%.
3. Слишком большой, повреждённый или не укладывающийся в бюджет клип даёт диагностируемый безопасный fallback; нет зависания, скрытого oversized-окна или скачка расхода памяти за рассчитанный бюджет.
4. Drag, пауза, отражение, соседние клики, ввод в другом приложении, скрытие/возврат и выход продолжают работать. При наличии второго монитора — перенос и отключение; если его нет, сценарий отмечается непроверенным.

Автоматически: граничные размеры/бюджеты, пропорции и ограничения, совместимость текущих кадров и все существующие тесты. На Windows дополнительно записать время загрузки и память; не выдавать оценки за измерения. После результата остановиться и ждать проверки, не начинать V02.

## 3. Графическая основа

Все этапы ниже **предложены, не реализованы**. Следующий выбирается только после приёмки предыдущего.

| ID | Один результат этапа | Основная проверка |
|---|---|---|
| V01 | Безопасные крупные PNG, окно и бюджет памяти | Четыре критерия выше; старый набор не сломан. |
| V02 | Проверяемая интерактивная область персонажа | Прозрачные поля пропускают клики в тестовое соседнее окно; непрозрачная фигура сохраняет drag/ПКМ. Без глобальных хуков и отключения всего ввода персонажа. |
| V03 | Явный pivot стоп и согласование размеров разных клипов | Смена тестовых размеров сохраняет глобальную опору, кроме необходимой коррекции у края; старый version=1 читается. |
| V04 | Ручное переключение idle/walk в работающем приложении | Меняется клип, а не координаты; нет повторного чтения на каждом кадре и лишних таймеров. |
| V05 | Устойчивые переходы между клипами | Есть завершение/отмена перехода; при отсутствии переходного арта нет скачка или сгенерированной позы. Проверка задержки UI. |
| V06 | Аудит и подключение качественного минимального набора | Источник/разрешение зафиксированы; idle/walk/sit/sleep и базовые эмоциональные позы визуально согласованы. Отсутствующий арт не объявлен готовым. |
| V07 | Компактная панель с портретом | Открывается по запросу, закрывается, ограничена по размеру; окно персонажа не расширяется. |
| V08 | Неоновая тема панели и меню | Текст читается на Windows DPI, нет постоянного мигания; декоративные эффекты отключаемы. |

Это не этапы автоматической генерации арта. Подготовка стороннего набора зависит от наличия качественных кадров и разрешения. При отсутствии набора фиксируется точный недостающий материал; возвращение к примитивной фигуре не считается исполнением V06.

## 4. Управление и автономность

| ID | Один результат этапа | Основная проверка |
|---|---|---|
| S01 | Настройки масштаба/поверх окон/активности с локальным сохранением | Перезапуск сохраняет только доступные настройки; повреждённый файл не ломает запуск; значения можно сбросить. |

| C02 | Короткая автономная прогулка по нижнему краю | Скорость по dt, границы, разворот, пауза и концентрация правил; drag прерывает прогулку. После отпускания нет потери персонажа. |
| C03 | Ожидание, сидение и сон с энергией/скукой | Минимальные длительности, нет дёрганья между состояниями; отсутствие нужного клипа обработано. |

В C02 до отдельного сервиса концентрации проверяется запрет движения по соответствующему входному флагу; полноценная настройка пользователем добавляется в T06. Utility scoring не обязателен для первого FSM; вводится только при необходимости после C04. Работа core не зависит от диалогов.

| ID | Один результат этапа | Основная проверка |
|---|---|---|
| T01 | Один или несколько таймеров с отменой и оставшимся временем | Истечение даёт одно ненавязчивое событие при видимом/скрытом/приостановленном персонаже. |

| T03 | Одноразовые напоминания по дате/времени | Создание, список, отмена, локальный часовой пояс и восстановление; истечение один раз. |
| T04 | Небольшие заметки | Создать/изменить/удалить, перезапустить, экспортировать; старые записи и данные при ошибке не исчезают. |
| T05 | Локальные часы в панели | Обновление по редкому общему такту, корректное время после сна/смены пояса, без сети. |
| T06 | Режим концентрации и общая очередь уведомлений | Декоративная активность прекращается, ручное управление доступно, созданные пользователем сроки сохраняются. |
| D01 | DialogueProvider и локальные темы/реплики | Без SDK/моделей; неизвестной теме — понятный fallback; выбор эмоции только из допустимого набора. |
| D02 | Контекст реплик и ограниченная память взаимодействий | Настроение, время суток и явная история влияют на реплики, нет спама; память можно отключить и очистить. |

Не помещать таймеры, заметки и SQLite в QWidget или FSM. Уведомления T01 минимальные; T06 объединяет их политики с концентрацией без второго независимого механизма уведомлений.

## 6. Первая полезная версия U1 и выход из неё

U1 объединяет минимальный качественный набор V01–V08, настройки S01, базовую автономность C01–C04, инструменты T01–T06 и сценарное общение D01–D02. Это несколько отдельных этапов, а не ближайшая одна задача. Функциональные критерии — [SPEC, раздел 7](SPEC.md#7-первая-действительно-полезная-версия-u1).

| ID | Финальный результат U1 | Основная проверка |
|---|---|---|
| R01 | Совместная проверка функций и ресурсов Windows | 15 минут на указанном ПК, офлайн, память/CPU, DPI, фокус, скрытие, сон/перезапуск и сохранённые данные. Задокументированы ограничения. |
| R02 | Воспроизводимая Windows-сборка | EXE на чистом тестовом окружении, ассеты включены, запуск/выход без Python и сети; права на распространяемый арт подтверждены. Автозапуск не включается. |

Главная ценность U1: персонаж выглядит согласованно, имеет несколько спокойных занятий, а таймеры, напоминания, заметки и концентрация полезны при отключённой автономности. Если искусства не хватает, сначала доводится ограниченный набор, не обещается огромная библиотека эмоций.

**После U1, только отдельными запросами:** объяснимые привычки; прыжки/падения; редкие действия с cooldown; расширенные портреты и сцены; обнаружение полноэкранных приложений; разрешённое управление музыкой; платформы на чужих окнах. Каждая интеграция описывает используемые данные и выключатель. LLM — отдельное будущее решение через DialogueProvider, не обязательство релиза.

## 7. Порядок работы Codex

1. Читать AGENTS/README/SPEC/ARCHITECTURE/ROADMAP, проверять Git и текущий код. README — навигатор, а не команда автоматически начать все этапы.
2. Назвать выбранный этап, файлы и критерии. Не создавать пустые модули «на будущее» и не расширять scope без просьбы.
3. Сохранить рабочие ассеты и совместимость, выполнить доступные осмысленные проверки. Для документации достаточно проверки согласованности/ссылок и подтверждения, что код не менялся; существующие тесты можно прогнать как baseline.
4. Сообщить факт/ограничения и команды PowerShell. Не называть Windows GUI проверенным по offscreen-тесту.
5. По постоянному разрешению пользователя создать отдельную ветку, коммит, push и PR в main. Если API запрещает создание PR — точная ошибка и ссылка для ручного создания. Не сливать PR самостоятельно.
6. Остановиться. Подтверждение текущего результата не означает разрешение реализовать весь новый план.

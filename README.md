# Rebecca Desktop Companion

**Версия концепции:** 0.1 (26.10.2026)  
**Статус:** этап 02 — перетаскивание; ожидает ручной проверки на Windows<br>
**Платформа:** Windows 11; Windows 10 — по возможности  
**Язык документации и интерфейса:** русский  
**Идея:** автономный пиксельный фан-персонаж Ребекка (*Cyberpunk: Edgerunners*), живущий поверх рабочего стола.

## Главное правило

Приложение **работает без какой-либо нейросетевой/языковой модели** и без интернета. Для действий, эмоций, привычек, памяти и диалогов используются обычные алгоритмы, локальные данные и подготовленные реплики. Будущая языковая модель — лишь отключаемое расширение для диалогов; без него приложение полностью функционально.

**Codex применяется для разработки, но не является частью работающего приложения.**

## Что пользователь должен получить

Маленькую пиксельную Ребекку, которая ходит по экрану, самостоятельно выбирает занятия, реагирует на курсор/клики, может сидеть, спать и иногда проявлять инициативу. Она должна быть живой по ощущениям, но ненавязчивой: не мешать кликам по приложениям, не отбирать фокус и не требовать постоянного внимания.

## Файлы документации

- `SPEC.md` — функциональные требования, границы и критерии готовности.
- `ARCHITECTURE.md` — модули, потоки данных, состояния, поведение, сохранения, интерфейс будущей модели.
- `ROADMAP.md` — маленькие последовательные этапы с проверками.
- `AGENTS.md` — обязательные правила работы Codex с репозиторием.
- `START_PROMPT.md` — первый запрос в Codex. Начинать только с него.

## Предпочтительные технологии

- Python 3.12+ (выбрать и зафиксировать совместимую версию при запуске проекта).
- PySide6/Qt6 — окна, прозрачность, спрайты, GUI, трей, таймеры.
- SQLite + JSON — локальная память, настройки, фразы и определения анимаций.
- `pytest` — тесты не зависящих от GUI модулей.
- `pywin32` / Win32 API — **только позднее и только там, где Qt недостаточно** (границы других окон, особенности Windows).
- PyInstaller — упаковка `.exe` после рабочего прототипа.

Версии зависимостей фиксировать **после проверки установки**. Не добавлять игровые движки, веб-сервер, фоновую службу, Electron или сетевые SDK без конкретной необходимости.

## Приоритет

1. Надёжный, прозрачный и ненавязчивый персонаж, которого можно схватить и переместить.
2. Плавная анимация и самостоятельная прогулка по экрану.
3. Состояния и действия, реакции и локальная память.
4. Продвинутая физика, взаимодействие с окнами и визуальные эффекты.
5. Опциональные системные/интернет-интеграции.
6. При желании — отдельный диалоговый ИИ-модуль.

**Важно:** расширенный список функций в `SPEC.md` — предложенный бэклог, а не утверждение, что каждая возможность обязательна в первой версии. Приоритеты можно менять по решению пользователя.

## Исходные материалы

Настоящие пиксельные спрайты нужно подготовить отдельно. На самом первом этапе достаточно временной фигуры или тестового PNG, чтобы не блокировать проверку архитектуры. Не загружать и не распространять чужие изображения, музыку или голосовые записи автоматически. Для фан-проекта использовать материалы с надлежащими правами и учитывать ограничения при публикации.

## Как начать

### Запуск прототипа (Windows PowerShell)

Нужен Python **3.12** (64-bit) с python.org. Откройте PowerShell в папке
этого репозитория, где находится `pyproject.toml`, и выполните:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m rebecca
```

Активация окружения и изменение ExecutionPolicy не нужны. Интернет необходим
только при первоначальной установке зависимостей. После установки повторный
запуск последней командой работает без сети и без моделей.
Проверенные версии: Python 3.12.14, PySide6 6.10.2.

На основном мониторе по центру нижней границы рабочей области появится
неподвижная временная пиксельная фигурка в окне **64×96 логических пикселей**.
Рабочая область берётся из Qt `availableGeometry()` и исключает панель задач.
Фигура рисуется локально, отдельные изображения не нужны. Закрытие:
**ПКМ по фигурке → «Выход»**. Удерживайте левую кнопку на фигурке, чтобы
перетащить её. Точка захвата сохраняется, окно удерживается в рабочей области
монитора под курсором, включая мониторы слева от основного. При отпускании
фигурка остаётся на новом месте; после перезапуска снова появляется над панелью
задач. При изменении рабочей области или отключении монитора позиция возвращается
в доступную область. Окно поверх обычных окон; скрытие в играх и трей пока
не реализованы. Автономного движения, физики и сохранения позиции нет.

Ручная проверка на Windows:

1. Видна только фигурка над панелью задач, без фона и рамки. Возьмите её
   левой кнопкой в разных местах: не должно быть скачка к центру курсора.
   После отпускания и движения мыши фигурка должна оставаться на месте.
2. Нажимайте кнопки и печатайте в другом приложении рядом с фигуркой:
   ввод должен работать, запуск персонажа не должен отбирать фокус.
   Внутри маленького прямоугольника 64×96 клики может получать персонаж,
   включая прозрачные участки; попиксельное пропускание пока не реализовано.
3. ПКМ по фигурке открывает единственный пункт «Выход»; выбор полностью
   завершает программу и возвращает приглашение PowerShell.
4. Перетащите фигурку к каждому краю и панели задач: окно должно оставаться
   в рабочей области. Если есть второй монитор, перенесите на него фигурку,
   затем отключите монитор: фигурка должна вернуться на доступный экран.
   Повторите с масштабом Windows 125–200% (в том числе разным на мониторах).

Автоматические проверки (стандартный `unittest`, без дополнительных зависимостей):

```powershell
.\.venv\Scripts\python.exe -m compileall -q src tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Один тест кратко показывает окно и меню. В Linux без дисплея перед тестами
задайте `QT_QPA_PLATFORM=offscreen`. Эти тесты проверяют размеры и флаги окна,
прозрачные пиксели графики, позицию в рабочей области с разными координатами,
контекстное меню и завершение цикла Qt. Также проверяются события перетаскивания,
сохранение точки захвата, остановка после отпускания, ограничения по краям
и выбор экрана (с подставными геометриями). Они не заменяют проверку нативного
поведения Windows. Остальная документация ниже описывает будущий проект;
следующие этапы не реализуются без подтверждения текущего результата.

### Исходный порядок подготовки документации

1. Создать пустую папку проекта, например `RebeccaDesktopCompanion`.
2. Положить внутрь все Markdown-файлы из этого набора.
3. Открыть эту папку в Codex.
4. Отправить содержимое `START_PROMPT.md`.
5. После первого этапа проверить окно на своём ПК и только затем разрешить следующий этап.

Не просить Codex реализовать весь проект одной командой.
